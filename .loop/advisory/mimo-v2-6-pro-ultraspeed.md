### public-api
**Verdict:** needs work
**Evidence:** `BaseChatModel::generatePrompt(array $promptValues, array $options = [], ?array $callbacks = null)` vs `BaseChatModel::generateMessages(array $messageLists, ?RunnableConfig $config = null, array $options = [])` (same class, quoted in §4); `Pregel::getState(RunnableConfig|array $config): array` and `getStateHistory(...): array`; `BaseChatModel::withStructuredOutput(array $schema, array $config = []): \LangChain\Runnables\Runnable` alongside `LangChain\Tools\Schema::__construct(public readonly array $schema)`.
**Finding:** Three concrete leaks. (1) The same class spells the option triple three ways — `array $options` then `?array $callbacks` in `generatePrompt`, `?RunnableConfig $config` then `array $options` in `generateMessages` — so a caller moving between the two must relearn argument order *and* type. (Upstream takes a Zod schema, so array-typed input is a justified divergence; *excluding the port's own schema class* is not.)
**Suggested change:** Normalise the options/config/callback triple to one order and one type across `generatePrompt`/`generateMessages`/`stream`; return a `StateSnapshot` value object (or at minimum a shape-documented array); widen the first parameter of `withStructuredOutput` to `Schema|array`.

## A. Composition — two journeys traced

Leg 2 (streaming tool calls) works at the message layer: `convertToChunk()` keeps tool calls and encodes empty args as `{}` (`ConvertToChunkTest`), with `AIMessageChunk`/`MessageMerge`/`ToolMessage` present as components. Leg 3 (checkpointing) works and is the best-guarded seam in the port — `LangGraph.Pregel.Checkpoint` 648 lines / **14** test files, and `SqliteSaver::list()`/`MemorySaver::list()` answer a `checkpoint_id` the same way (§5, iteration 127).

It dead-ends at two seams the brief does not cover:
1. **chunk → message → channel.** A streaming node produces `AIMessageChunk`s; `RunnableSequence` forwards chunk-typed stepInput. Nothing printed shows where the chunk is merged into an `AIMessage` before a channel write, and `LangGraph.Channels` (1492 lines) has **2** test files.
2. **interrupt/resume.** `NodeInterrupt` and `GraphInterrupt` exist in the taxonomy, and `Pregel` can `getState()`/`getStateHistory()` — but its six public methods include **no `updateState()`**. Upstream `CompiledGraph` exposes `updateState` precisely to steer an interrupted, checkpointed run. As printed, a checkpointed interrupt can be *observed* and not *steered*, which is a hard stop for any human-in-the-loop journey. (Hedge: the brief truncates the constructor and does not enumerate sibling classes; if `updateState` lives elsewhere, this leg is fine and the fix is documentation.)

**Journey 2 — `$prompt | $model->withStructuredOutput($schema, ['includeRaw' => true])` streamed.**
This one works end to end on the record: `withStructuredOutput` returns a `Runnable`, the `{raw: llm, parsed: parser}` pipeline is exactly the `RunnableParallel` case whose scalar-input regression is pinned (`testParallelPassesScalarInputToEveryBranch`), `RunnableBinding` merges bound kwargs into `config->options` (fixed, tested, precedence pinned upstream-side), `RunnableSequence::stream()` streams every step (mutation-verified, iteration 55), and `stepConfig()` no longer clobbers `runName`.
